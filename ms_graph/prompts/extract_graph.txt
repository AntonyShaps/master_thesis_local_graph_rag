
-Goal-
Given a text document from a corporate sustainability or ESG report and a list of entity types, identify ESG-relevant entities of those types and explicit relationships among them.

Prioritize facts that support retrieval for sustainability questions: emissions scopes, climate targets, renewable or carbon-free electricity, supplier programs, waste, water, governance, reporting frameworks, products, and measurable initiatives.

-Quantitative Data Rules-
1. Preserve all numbers exactly as written in the source text (no rounding, conversion, normalization, or inferred values).
2. Preserve units and symbols exactly (for example: %, tCO2e, MWh, kWh, USD, million, billion, x, m3, PFLOP).
3. Preserve period and scope for each value (for example: FY25, baseline year, scope 1/2/3, region, per-unit basis).
4. For table-like text, treat each row as a separate fact and keep metric label + value + unit + period.
5. If a value is missing, do not fabricate it.

-Noise Rejection Rules-
1. Ignore chart rendering labels, axis labels, legends, page numbers, HTML tags, image placeholders, page headers, page footers, OCR fragments, and table formatting artifacts unless they are part of a complete ESG fact.
2. Do not create entities for standalone numbers, percentages, axis tick labels, years, figure labels, or generic words unless they are needed as a time_period or part of a named ESG metric.
3. Do not emit malformed records, parser instructions, prompt text, or the token <|COMPLETE|> inside an entity or relationship field.
4. Examples are formatting demonstrations only. Do not copy example entities, values, or relationships into the final output unless they are explicitly present in the Real Data text.

-Output Validity Rules-
1. Emit each unique entity only once per extraction pass.
2. Emit each unique relationship only once per extraction pass.
3. Use the exact output format and delimiters.
4. If nothing is found, output only <|COMPLETE|>.
5. The only valid record formats are:
("entity"<|><entity_name><|><entity_type><|><entity_description>)
("relationship"<|><source_entity><|><target_entity><|><relationship_description><|><relationship_strength>)
6. relationship_strength must be a single integer from 1 to 10 in the final field only.
7. End the output with exactly one <|COMPLETE|> token and do not write anything after it.

-Steps-
1. Identify all entities. For each identified entity, extract the following information:
- entity_name: Name of the entity, capitalized
- entity_type: One of the following types: [{entity_types}]
- entity_description: Comprehensive description of the entity's attributes and activities. Keep quantitative facts explicit in this compact form when available: metric=<metric>; value=<value>; unit=<unit_or_NONE>; period=<period_or_NONE>; scope=<scope_or_NONE>
Format each entity as ("entity"<|><entity_name><|><entity_type><|><entity_description>)

2. From the entities identified in step 1, identify all pairs of (source_entity, target_entity) that are clearly related.
For each pair of related entities, extract the following information:
- source_entity: name of the source entity, as identified in step 1
- target_entity: name of the target entity, as identified in step 1
- relationship_description: explanation of why the source and target are related. Include quantitative evidence when present, preserving exact value, unit, and period.
- relationship_strength: an integer score between 1 and 10 indicating strength of the relationship
Format each relationship as ("relationship"<|><source_entity><|><target_entity><|><relationship_description><|><relationship_strength>)

3. Relationship requirements:
- Every metric, target, initiative, product, supplier_program, reporting_framework, governance_body, or emissions_scope entity must have at least one relationship to the reporting company, a relevant period, a scope, or a program in the same text. If no relationship is clear, omit that entity.
- Connect ESG metrics directly to the company whenever the company reports, achieves, targets, or discloses the metric.
- Connect time_period entities to the metric, target, or initiative whose value applies during that period.
- Connect reporting frameworks and governance bodies to the company or to the relevant disclosure/governance process.
- Connect products and initiatives to the ESG outcome they enable.

4. Return output in English as a single list of all entities and relationships identified in steps 1 and 2. Use **##** as the list delimiter.

5. If you must translate into English, translate descriptions only.

6. When finished, output <|COMPLETE|>.
